## 1. 产品定位与边界

**一句话：** 家药箱先帮你在家里**找到药**；若这次属于一个疗程，再帮你**按时吃、全家看得见**。

| 优先级 | 能力 | 含义 |
|--------|------|------|
| P0 | **B 找药** | 包装照对照、药名/适应症、位置、效期、库存 |
| P1 | **A 疗程依从** | 医嘱/连服计划、多药钟点提醒、确认服用、流水 |
| P1 | **C 家庭协同** | 一人录入全家找；代确认服用；主要照护人收推送 |

**不做：** 诊断、用药/剂量建议、购药导流、替代就医。  
计划由用户按医嘱或说明书自填；界面固定免责：「请按说明书或医嘱服用」。

**与医院的分工：** 医院负责该不该吃、吃什么；本产品负责药在哪、今天该吃哪几种、有没有吃、还剩多少。

## 2. 信息架构（双轨）

底栏：**药品 | 事件 | 我的**

### 2.1 药品 Tab（默认，找药主路径）

- 搜索、包装照药卡、效期与库存
- 详情 → 确认取用
- 有「今日待服」时，顶部**一条克制提醒条**（点进对应事件），不挡找药

### 2.2 事件 Tab（加重，疗程本）

- 进行中 / 已结束事件列表
- 事件详情：基本信息、用药计划、今日待服、流水、复评状态
- 新建轻量事件、添加/编辑用药计划、结束事件

### 2.3 我的

- 家庭成员、登录、通知权限等设置（真机）

## 3. 核心对象

### 3.1 健康事件

| 字段 | 说明 |
|------|------|
| 谁 | 家庭成员或称谓（孩子/妈妈等） |
| 标题 | 如「感冒发烧」「降压疗程」 |
| 开始日 | 日期 |
| 状态 | 进行中 / 已结束 |
| 复评天数 | 可选；满 N 天提示复评/就医（与服药提醒分开） |
| 主要照护人 | 可选；默认收推送。未指定时默认为**创建该事件的人** |

### 3.2 用药计划（挂在事件下，可多条）

| 字段 | 说明 |
|------|------|
| 药品 | 关联药箱中的药（展示包装缩略图） |
| 每次用量 | 数量 + 单位 |
| 提醒钟点 | 一个或多个（如 08:00 / 20:00） |
| 起止 | 开始日 + 结束日，或「共 N 天」 |
| 提醒开关 | 开/关 |

### 3.3 待服（由计划按日生成）

状态：`待服` | `已服` | `漏服` | `稍后`

### 3.4 流水

时间、药、量、来源（提醒确认 / 手动取用）、操作者（谁确认的）

## 4. 主路径

### 4.1 找药取用（B）

```
药品首页 → 对照包装 → 详情 → 确认取用 → 扣库存
```

取用与事件的关系：

| 情境 | 行为 |
|------|------|
| 从某事件「去取药 / 确认待服」进入 | **必须**记入该事件 |
| 药品详情取用，仅 1 个进行中事件 | **默认带入**该事件（可改为快速取用） |
| 药品详情取用，≥2 个进行中事件 | **必须先选**关联哪个事件（或快速取用） |
| 保健/偶发、无进行中事件 | **快速取用**（仅扣库存） |

> 修正早期「一律必关联」：找药优先畅通；疗程场景再强制记入事件。

### 4.2 疗程（A）

```
事件 Tab → 建轻量事件（谁/标题/开始日）
        → 添加用药计划（多药 × 钟点 × 天数）
        → 系统生成待服 → 推送
        → 确认服用 → 扣库存 + 流水
        →（可选）满 N 天复评提醒
        → 标记结束 → 停计划与提醒
```

建事件时**不强制**配齐计划；创建后引导「添加用药计划」，可稍后补。

## 5. 提醒引擎（完整 C）

1. **到点推送**：药名 + 包装缩略 + 事件名  
2. **确认服用**：扣库存 + 流水「已服」  
3. **稍后**：15 / 30 / 60 分钟再提醒  
4. **跳过本次**：记漏服，不扣库存  
5. **事件结束或计划到期**：自动停止提醒  

**呈现：**

- 事件详情：今日待服列表（待服 / 已服 / 漏服）
- 首页：仅未完成待服时显示提醒条
- 文案克制，不恐吓；不自动建议补服剂量
- **复评提醒**与**服药提醒**分开展示

**原型 vs 真机：**

- 原型：模拟今日待服、确认/漏服、推送预览卡（不接真实 APNs）
- 真机：系统通知；无权限时降级为 App 内待服

---

## 6. 家庭协同

- 共享：库存、事件、计划、待服、流水（全员对等可见可操作，与现有家庭策略一致）
- 推送：默认发给事件的「主要照护人」；其他人仍可在 App 内看到待服并**代确认**
- 流水记录操作者，便于追溯「是谁点的确认」

---

## 7. 原型验收要点（本轮）

1. 事件 Tab 可建轻量事件，并可添加 ≥2 条用药计划（多钟点）  
2. 事件详情展示今日待服；可确认服用 / 跳过；确认后库存减少且流水增加  
3. 药品首页在有待服时出现提醒条；找药网格不被打断  
4. 从事件确认待服必带事件；从药品快速取用可不关联  
5. 推送预览卡可演示（模拟）  
6. 结束事件后，该事件待服与提醒不再生成  

---

## 8. 非目标（本规格不做）

- 智能推荐吃什么药 / 算剂量  
- 药店购药跳转  
- 复杂医嘱识别（拍照处方 OCR）——可后续  
- 真实推送证书与后端调度（真机阶段再做）
